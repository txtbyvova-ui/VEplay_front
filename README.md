# VEgroove Play

Музыкальный плеер-«винил» для заведений. Локальный Node-сервер раздаёт треки,
React-фронтенд их проигрывает. У клиента один из двух режимов воспроизведения:

- **по времени суток** — музыка разложена по папкам `morning` / `day` / `evening`,
  плеер сам переключает категорию по часам (6–12 / 12–18 / 18–6);
- **единый плейлист** — одна папка `all`, играет весь день по кругу без расписания.

Доступ — по логину/паролю: каждый клиент видит и слышит только свою папку.
Есть веб-админка: клиенты, загрузка музыки, перенос треков и автоматическая
раскладка целой папки по времени суток (мост к классификатору VEclassify).

## Требования

- Node.js 18+ (проверено на Node 24). `node -v` должен работать.
- Только для кнопки «Классифицировать папку» — развёрнутый рядом VEclassify
  (Python 3.12 + librosa + рабочий Gemini-ключ), см. `README_DEPLOY.md`, шаг 5б.
  Без него всё остальное работает как обычно.

## Структура музыки: 1 клиент = 1 папка

```
<MUSIC_ROOT>/
  <folderId клиента>/          # например kafe-myatnaya-utka — режим «по времени суток»
    morning/   *.mp3 *.wav *.flac *.m4a *.aac *.ogg *.opus
    day/
    evening/

  <folderId другого клиента>/  # режим «единый плейлист»
    all/

  _incoming/                   # staging классификатора, сервер создаёт и чистит сам
```

Каждый клиент — отдельная папка; пользователь клиента привязан к ней через
`folderId` в `users.json` и видит только её. Админ видит все папки. Папка, логин и
случайный пароль создаются автоматически в админке («Создать клиента») — там же
выбирается режим воспроизведения.

Имена, начинающиеся с `_`, зарезервированы (`_incoming`) и никогда не считаются
папкой клиента.

Имя файла `Artist - Title.mp3` разбирается на исполнителя и название.
По умолчанию `MUSIC_ROOT` указывает на `../VEplay_demo` рядом с проектом
(для новой схемы вложите демо-треки в подпапку клиента). Свой путь:

```powershell
$env:MUSIC_ROOT = "E:\Clients_music"
```

Где лежат `users.json`, `.secret` и `pending_batches.json`, задаёт `DATA_DIR`
(по умолчанию — рядом с `server.mjs`; на проде — `/var/vegroove`, см. `README_DEPLOY.md`).

## Запуск

Нужны два процесса — бэкенд (порт 3001) и фронтенд (порт 5173).

```powershell
# 1) установка зависимостей (один раз)
npm install

# 2) бэкенд — раздача музыки + авторизация
npm run server

# 3) в другом окне — фронтенд (dev)
npm run dev
```

Открыть http://localhost:5173.

Прод-сборка фронтенда: `npm run build` → статика в `dist/` (раздаётся любым
статик-сервером; бэкенд `server.mjs` всё равно должен работать).

## Проверки

```powershell
npm run lint          # eslint по фронтенду
npm run build         # tsc -b && vite build → dist/
npm run check:server  # строгая проверка типов plain-JS сервера (tsc -p jsconfig.json)
npm run test:server   # тесты сервера: роуты классификатора, таймауты, восстановление батчей
```

`npm run test:server` хермётный: не нужна ни музыка, ни Python — классификатор
подменяется `test/stub_classify.mjs`, а `MUSIC_ROOT`/`DATA_DIR` уезжают в temp.

Отдельно, вручную: `node test/real_bridge_smoke.mjs "<папка с mp3>"` — сквозной
прогон с настоящим VEclassify, и `node scripts/test-upload.mjs` — диагностика загрузок.

## Авторизация и админка

- При первом запуске сервер создаёт администратора **`admin` / `admin`** и пишет
  об этом в консоль. **Смените пароль сразу** (в админке → «Мой пароль»).
  Логин/пароль администратора по умолчанию можно переопределить переменными
  `ADMIN_USER` / `ADMIN_PASS` до первого запуска.
- Пользователи и их доступы хранятся в `users.json` (в `DATA_DIR`). Пароли — в виде
  `scrypt`-хешей. Файл и секрет `.secret` в `.gitignore` — **не коммитьте их**.
- Войдя как admin, нажмите «Админка»: создание и удаление клиентов, сброс пароля
  (показывается один раз — сервер хранит только хеш), загрузка и перенос треков.
- Обычный пользователь видит и слышит только разрешённые ему категории своей папки.
  Стриминг защищён токеном: чужую папку нельзя открыть даже по прямой ссылке.

### Флаги клиента

В карточке клиента, блок «Доступно клиенту» — что показывать в плеере:

| Флаг | Что выключает |
|------|---------------|
| `allowFolderSelector` | нижний переключатель категорий (morning / day / evening) |
| `allowShuffle` | кнопку случайного порядка |

Флаги работают по принципу **opt-out**: отсутствующее значение читается как
«разрешено», поэтому клиенты, созданные до появления флагов, ничего не теряют.

## Загрузка музыки

**Вручную, по категории** — drag-and-drop или выбор файлов в карточке клиента:

- форматы: `.mp3` `.wav` `.flac` `.m4a` `.aac` `.ogg` `.opus`
  (тот же список используется при чтении папки, так что принятый файл всегда виден в библиотеке);
- до **200 МБ на файл**; лимита на количество файлов за один раз нет;
- каждый файл принимается или отклоняется индивидуально — ответ содержит
  `accepted` и `rejected` с причиной (`size` / `ext` / `name` / `write_error`),
  и админка показывает список отклонённых;
- совпадающие имена не перетирают друг друга: файл получает суффикс (`name_2.mp3`).

**Классификатор папки** (только для режима «по времени суток») — кнопка
«✨ Классифицировать папку» загружает целый каталог, VEclassify раскладывает треки
по `morning` / `day` / `evening`, и админ в модалке проверяет результат
(прослушать, поправить категорию) перед применением:

- берутся только `.mp3` — остальное попадает в `skipped`;
- до **500 файлов** и до **2 ГБ** на батч (`MAX_UPLOAD_BYTES`), сверх — `413`;
- один прогон классификатора ограничен `CLASSIFY_TIMEOUT_MS` (по умолчанию 1 час):
  зависший Python убивается, батч уходит в статус `error`, сервер остаётся жив;
- файлы лежат в `MUSIC_ROOT/_incoming/<batchId>/` до подтверждения; состояние батчей —
  в `DATA_DIR/pending_batches.json`, поэтому батч со статусом `ready` переживает
  рестарт сервера;
- «Отменить» на любом этапе удаляет staging; закрытие модалки = отмена.

## API (кратко)

Токен передаётся либо заголовком `Authorization: Bearer <token>`, либо параметром
`?token=` (для `<audio>`, который не умеет заголовки). Срок жизни токена — 30 дней.

### Публичное / плеер

| Метод | Путь | Доступ |
|-------|------|--------|
| POST | `/auth/login` | публично (rate-limit 10 попыток / 15 мин на IP) |
| GET | `/auth/me` | токен |
| GET | `/library` | токен — разрешённые категории своей папки (admin: все папки) |
| GET | `/tracks?category=` | токен — категория (недоступная подменяется на текущую по времени) |
| GET | `/music/:folder/:cat/:file?token=` | токен + проверка папки и категории; поддержан `Range` |

### Админ (роль `admin`)

| Метод | Путь | Что делает |
|-------|------|-----------|
| GET | `/admin/users` | список пользователей |
| POST | `/admin/users` | создать пользователя |
| PUT | `/admin/users/:name` | пароль / категории / роль / `folderId` / флаги |
| DELETE | `/admin/users/:name` | удалить (последнего админа — нельзя) |
| GET | `/admin/categories` | счётчики треков по категориям (по всем папкам) |
| GET | `/admin/clients` | клиенты: папка, логин, режим, флаги, счётчики, размер |
| POST | `/admin/clients` | создать клиента (`{ name, single_playlist? }`) → логин и пароль **один раз** |
| DELETE | `/admin/clients/:folderId` | удалить папку со всей музыкой и её пользователя |
| POST | `/admin/clients/:folderId/reset-password` | новый пароль (показывается один раз) |
| GET | `/admin/clients/:folderId/tracks` | треки по категориям |
| POST | `/admin/clients/:folderId/upload?category=` | multipart, поле `tracks`, ≤ 200 МБ/файл |
| POST | `/admin/clients/:folderId/:cat/:file/move` | перенести трек (`{ toFolderId, toCategory }`) |
| DELETE | `/admin/clients/:folderId/:cat/:file` | удалить трек |

### Админ — мост VEclassify

| Метод | Путь | Что делает |
|-------|------|-----------|
| POST | `/admin/clients/:folderId/classify` | multipart: залить папку в staging и запустить классификацию → `{ batchId }` |
| GET | `/admin/classify/:batchId` | состояние батча (`classifying` / `ready` / `error` / `confirming`) — фронт поллит его |
| POST | `/admin/classify/:batchId` | повторить классификацию (только из статуса `error`) |
| PUT | `/admin/classify/:batchId/track/:file` | переопределить категорию трека |
| GET | `/admin/classify/:batchId/track/:file/audio` | прослушать трек из staging (`Range`) |
| POST | `/admin/classify/:batchId/confirm` | разложить файлы в `MUSIC_ROOT/<folderId>/<category>` |
| DELETE | `/admin/classify/:batchId` | отменить батч и удалить staging |

## Конфигурация фронтенда

`.env`:

```
VITE_API_BASE=http://localhost:3001
```

На проде фронт и API живут на одном домене за Caddy, поэтому `.env.production`
содержит **пустой** `VITE_API_BASE` — запросы уходят относительными путями.
См. `.env.example` (там же перечислены переменные рантайма `server.mjs`).
