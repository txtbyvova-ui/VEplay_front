# План: устранение находок аудита (2026-07-31)

Документ фиксирует результат мульти-агентного аудита кодовой базы на утечки памяти
и баги и раскладывает найденное на четыре независимых PR. Формат — как у
`TZ_IOS_PLAYER_FIXES.md`: привязка к реальному коду, сценарий отказа, конкретная
правка, критерий приёмки.

**Состояние на момент составления:** прод на `b5eda70`, всё из PR #1–#7 раскатано.

---

## Как это получено

- 6 независимых срезов (плеер, кэш IndexedDB, React-гигиена, админка, ресурсы
  сервера, корректность сервера), по каждому — отдельный проход и затем
  состязательная проверка находок скептиком, которому поставлена задача их
  **опровергнуть**. 12 агентов, 209 инструментальных вызовов.
- Параллельно — измерения в реальном Chrome через DevTools Protocol: снимки кучи
  после принудительной сборки мусора, счётчики blob-URL / слушателей / таймеров,
  подсчёт мутаций DOM. См. «Воспроизведение измерений» в конце.

**Итог:** 21 находка подтверждена, 6 остались без вердикта (см. §6), 4 опровергнуты
(см. §7).

### Что измерения показали само по себе

| Проверка | Результат |
|---|---|
| 80 переключений трека, куча после GC | 17.3 → 17.7 МБ (+5 КБ на переключение) |
| detached DOM-узлы за тот же прогон | 0 → 0 |
| Живых blob-URL при 60 переключениях | ровно 1 (создано 60, отозвано 59) |
| Слушателей на `<audio>` добавлено за прогон | 0 |
| Мутаций DOM при обычном воспроизведении | 9.1/с (заливка таймлайна и таймер) |
| **Заход в админку и обратно** | **+4 `MediaElementSource`, ни один не освобождён** |

Утечки в пути переключения трека нет. Утечка есть на переходе плеер↔админка —
и именно её прогон переключений не видел, потому что админку не открывал.

## 1. PR «Живучесть сессии и звука» — брать первым

Здесь всё, что прямо сейчас способно оставить зал без музыки без возможности
восстановиться силами персонала.

### 1.1 Сетевая ошибка `/auth/me` стирает токен  `[critical]`

**Где:** `src/auth/AuthContext.tsx:30-44`

**Симптом.** Единственный `.catch` без разбора причины:

```js
.then(r => (r.ok ? r.json() : Promise.reject(new Error('unauthorized'))))
.catch(() => { localStorage.removeItem(TOKEN_KEY); … })
```

В эту ветку попадают три разных случая: настоящий 401, реджект `fetch`
(`TypeError: Failed to fetch` при отсутствии сети) и любой не-2xx, включая 502/503
от Caddy во время нашего же `deploy.sh`. Токен удаляется безвозвратно.

**Сценарий отказа.** Утром iPad поднялся раньше Wi-Fi, либо страница
перезагрузилась в момент деплоя → экран логина. Пароль клиента показывается
**один раз** (`CredentialsModal`), сервер хранит только хеш — восстановить на
месте нечем. Тишина в зале до приезда администратора. Мы деплоили трижды за день,
так что окно не гипотетическое.

**Правка.** Прокинуть статус в ошибку и чистить хранилище только на 401/403:

```js
.then(r => (r.ok ? r.json() : Promise.reject(Object.assign(new Error('unauthorized'), { status: r.status }))))
.catch(e => {
  if (cancelled) return
  if (e?.status === 401 || e?.status === 403) { /* токен мёртв — чистим */ }
  else { /* сеть/сервер — токен оставляем, показываем состояние «нет связи» с ретраем */ }
})
```

Эффект имеет `deps: []`, поэтому при возврате сети повторной валидации не будет —
добавить ретрай с бэкоффом либо повтор на `online`/`visibilitychange`.

**Критерий приёмки.** Остановить бэкенд, перезагрузить страницу: токен в
localStorage остался, показано «нет связи», после подъёма бэкенда сессия
восстанавливается без ввода пароля. Настоящий 401 (подделать токен) по-прежнему
приводит к экрану логина.

### 1.2 Нет слушателя `error` на `<audio>`  `[high]`

**Где:** `src/hooks/usePlayer.ts:590-595`

**Симптом.** Навешаны только `timeupdate`, `durationchange`, `ended`, `play`,
`playing`, `pause`. Любая ошибка источника (битый файл, отозванный blob, отказ
декодера) не даёт ни `ended`, ни `timeupdate` — автопереход не срабатывает, плеер
стоит до ручного вмешательства.

**Правка.** Слушатель `error` на обоих элементах: если сторона активна — сбросить
запись из кэша (байты могли быть битыми), перезагрузить сторону с сетевого
`track.src`, при повторной ошибке — перейти к следующему треку. Это же страхует
все остальные находки, где источник может оказаться нерабочим.

**Критерий приёмки.** Подменить в кэше байты трека на мусор → плеер
логирует ошибку, перезагружается с сети и продолжает играть, а не встаёт.

### 1.3 Кэш теряет MIME-тип  `[high]`

**Где:** `src/audio/cache.ts:130,134,182`; `CacheRecord` — `cache.ts:18-23`

**Симптом.** `fetchAndCache` берёт только `r.arrayBuffer()` и выбрасывает
заголовки, в `CacheRecord` поля под тип нет, `playableUrl` делает
`new Blob([buf])` без `{ type }` → `blob.type === ''`. По сети сервер отдаёт
корректный `Content-Type` (`server/streaming.mjs`, таблица `MIME` в
`config.mjs:89-97`), то есть кэш ломает то, что по сети играло.

**Оговорка.** Chromium снифферит контейнер и играет — локально это подтвердилось.
Риск на WebKit, где у `blob:` нет ни типа, ни расширения для вывода MIME.
Непроверено на реальном iPad, но правка дешёвая и снимает целый класс риска.

**Правка.** Хранить тип: `mime: r.headers.get('content-type') || ''` в
`CacheRecord`, `new Blob([buf], { type: rec.mime || mimeByExt(rec.url) })`;
для старых записей без поля — дефолт по расширению.

**Критерий приёмки.** На iPad второй круг плейлиста (когда треки уже в кэше)
играет так же, как первый.

## 2. PR «Админка не глушит плеер, граф не растёт»

### 2.1 Открытие админки размонтирует плеер  `[medium]`

**Где:** `src/App.tsx:25`

```jsx
if (view === 'admin' && user.role === 'admin') return <AdminPanel onBack={…} />
return <PlayerScreen … />
```

**Симптом.** `AdminPanel` рендерится **вместо** `PlayerScreen` → `usePlayer`
размонтируется → cleanup ставит оба элемента на паузу. Оператор жмёт «Админка»,
чтобы залить папку, — музыка в зале обрывается на середине трека. Классификация,
по собственному тексту UI, «может занять несколько минут» — всё это время тишина.
При возврате плеер стартует с паузы.

**Проверено замером:** в админке `.player-btn-play` в DOM отсутствует.

**Правка.** Не размонтировать плеер, а прятать: рендерить обе ветки, неактивную
скрывать через `display: none`, админку показывать поверх. Проверить, что скрытый
плеер продолжает играть (звук от `display: none` не зависит).

**Критерий приёмки.** Открыть админку во время воспроизведения — музыка не
прерывается; вернуться — плеер продолжает тот же трек с той же позиции.

### 2.2 Ноды графа не отцепляются при размонтировании  `[medium, leak]`

**Где:** `src/hooks/usePlayer.ts:201-210` (cleanup), `src/audio/graph.ts`

**Симптом.** Cleanup делает `cancelPreload()`, `pause()` обоих элементов и
`revoke` blob-URL. Ни `source.disconnect()`, ни `gain.disconnect()`, ни снятия
`src` нет. В `graph.ts` вообще **нет экспорта `detach`** — только `attach`.
`sources` (WeakMap) и `AudioContext` живут на уровне модуля и переживают
размонтирование. При новом монтировании `make()` создаёт **новые** `new Audio()`,
`attach` промахивается мимо WeakMap и создаёт новую пару нод, подключая её к тому
же компрессору. Старые остаются подключёнными — а значит удерживаются вместе со
своими `<audio>`.

**Проверено замером:** один заход в админку и обратно = **+4
`MediaElementSource`** (32 → 36; dev-сборка удваивает из-за StrictMode, в проде
+2), ни один не освобождается.

> Это уточняет комментарий в `graph.ts:30-38` про «FIXED set … never grown»:
> инвариант верен в пределах одного монтирования, но нарушается при
> размонтировании хука. Комментарий поправить.

**Правка.** Добавить в `graph.ts`:

```ts
export function detach(el: HTMLAudioElement): void {
  const s = sources.get(el)
  if (!s) return
  try { s.source.disconnect(); s.gain.disconnect() } catch { /* ignore */ }
  sources.delete(el)
}
```

и звать для обоих элементов в cleanup, там же снимать `src` и делать `load()`.
После 2.1 размонтирование станет редким, но правка нужна независимо: хук
размонтируется и при выходе из аккаунта.

**Критерий приёмки.** Счётчик `createMediaElementSource` не растёт при
многократных переходах плеер↔админка↔выход↔вход.

## 3. PR «Кэш и очередь»

### 3.1 Квота IndexedDB встаёт намертво  `[medium]`

**Где:** `src/audio/cache.ts:99-115`

`putCached` при провале записи зовёт `evictLRU(Math.floor(MAX_ENTRIES / 2))`, то
есть `evictLRU(25)`. Но `evictLRU` удаляет **только** когда записей больше
переданного максимума. При крупных файлах (WAV/FLAC/длинные миксы) квота
кончается на 8–12 записях — `evictLRU(25)` не удаляет ничего, повторная запись
падает снова, и так навсегда. Дальше `isCached` всегда false, и `preload` после
каждой смены трека заново тянет три полных файла.

**Правка.** Бюджет считать в байтах, а не в записях: хранить суммарный размер,
вытеснять до порога (например 300 МБ); отказываться кэшировать файл крупнее
per-file cap, иначе один большой трек вытеснит весь кэш. При провале записи
вытеснять по фактически освобождённым байтам, а не по числу записей.

### 3.2 `lastUsed` переписывает весь ArrayBuffer трека  `[low, perf]`

**Где:** `src/audio/cache.ts:66`

```js
try { tx(db, 'readwrite').put({ ...rec, lastUsed: Date.now() }) } catch {}
```

Ради обновления метки времени в IndexedDB переписываются все байты трека —
structured clone на 8–30 МБ в главном потоке, ровно в момент старта трека
(то есть на кроссфейде). Плюс износ флеша iPad: ~480 таких записей за сутки.

**Правка.** Держать LRU-штампы в отдельном object store (`{ url, lastUsed }`) с
индексом по `lastUsed`, `evictLRU` водить курсором по нему.

### 3.3 Кэш не инвалидируется при перезаливке трека  `[low]`

**Где:** `src/audio/cache.ts:26-28` (`cacheKey` отрезает query целиком)

Ключ — только путь. Админ заливает исправленный файл под тем же именем — на
планшете неделями играют старые байты.

**Правка.** Внести версию в ключ: `scanFolder` добавляет к `src` `?v=<mtime_ms>`,
`cacheKey` вырезает только `token`, оставляя `v`.

### 3.4 Ротация по времени суток подменяет очередь под играющим треком  `[medium]`

**Где:** `src/hooks/usePlayer.ts:315` (интервал ротации)

В 12:00/18:00 `setTracks` + `setOrder` + `setOrderPos(0)` выполняются немедленно,
хотя из колонок ещё играет трек прошлой категории. Экран показывает первый трек
новой подборки, а `saveSession` пишет имя нового трека с позицией старого —
порча точки возобновления.

**Правка.** Не сбрасывать очередь под играющим элементом: либо запомнить новую
очередь в ref и применить в момент следующего `switchTo`, либо сразу выполнить
`switchTo(0, CROSSFADE_SEC)` после `setOrder`, чтобы состояние и звук совпали.

### 3.5 `switchCategory` меняет заголовок до проверки списка  `[medium]`

**Где:** `src/components/PlayerScreen.tsx:394`

```js
setActiveCat(cat)
const list = library[cat] ?? []
if (list.length > 0) replaceQueueAndPlay(list, 0)
```

При сбое `/library` (`useLibrary` кладёт ошибку в state, но UI её не показывает)
кнопка подсвечивается активной, шапка врёт, играет старая категория. Повторный
клик по той же кнопке уходит в ранний `return` по `cat === activeCat`.

**Правка.** Менять `activeCat` только когда очередь действительно подменилась;
достать `error` из `useLibrary` и показать состояние загрузки/ошибки.

### 3.6 `ended` может удвоить переход  `[medium]`

**Где:** `src/hooks/usePlayer.ts:581`

На iOS окно хэндоффа `HANDOFF_SEC` = 0.4 с, а `timeupdate` приходит примерно раз
в 250 мс. Если чтение трека из IndexedDB и создание Blob не уложились в остаток
окна, трек доигрывает до конца, и `onEnded` на всё ещё активной стороне запускает
**второй** `switchTo` — плеер перескакивает трек.

**Правка.** В `onEnded` не наступать на идущее переключение: выходить, если
`crossfading.current` уже взведён.

### 3.7 Пауза не глушит уходящую сторону  `[low]`

**Где:** `src/hooks/usePlayer.ts:517`

На десктопе кроссфейд длится 6 с. Если оператор жмёт Pause внутри этого окна,
`togglePlay` останавливает только активную сторону — уходящая доигрывает до
своего отложенного `pause()`, то есть до 6 секунд музыки после нажатия паузы.

**Правка.** В ветке паузы глушить обе стороны и снимать запланированный доигрыш
(держать id таймаута остановки в ref).

### 3.8 Восстановление позиции применяется к чужому треку  `[low]`

**Где:** `src/hooks/usePlayer.ts:275` (две находки об одном месте)

```js
const startIdx = saved ? Math.max(0, list.findIndex(t => t.filename === saved.filename)) : 0
```

`findIndex` вернёт `-1`, если сохранённый файл удалён/переименован/перенесён
(в админке есть и delete, и move) — `Math.max(0, -1)` даёт 0, и позиция из
прошлой сессии применяется к **первому треку списка**: он стартует с середины.

**Правка.** Различать «нашли» и «не нашли»: применять `saved.position` только при
`found >= 0`, иначе стартовать с нуля, восстанавливая лишь категорию и shuffle.

## 4. PR «Админка и сервер»

### 4.1 Модалка классификации становится незакрываемой при 404  `[medium]`

**Где:** `src/components/ClassifyBatch.tsx:108`

Батч исчез на сервере (рестарт во время классификации) → фронт получает 404, но
`request()` не различает статусы, и 404 обрабатывается как обрыв связи: вечное
«Нет связи с сервером — продолжаем попытки…», GET каждые 15 с, выход только
перезагрузкой страницы.

**Правка.** Прокинуть HTTP-статус в ошибку `request()`; при 404 переводить
модалку в терминальное состояние с кнопкой закрытия.

### 4.2 Staged-батч теряется при уходе со страницы  `[medium, resource]`

**Где:** `src/components/admin/ClientCard.tsx:122`

`batchId` живёт только в state компонента. Уход на плеер, выход или перезагрузка
вкладки — и батч недостижим: файлы остаются в `_incoming/<uuid>` (до 2 ГБ),
запись — в `pending_batches.json`, и это переживает рестарты.

**Правка.** Хранить `batchId` в `localStorage` под ключом папки, восстанавливать
модалку при монтировании. На сервере — `GET /admin/classify` со списком живых
батчей, чтобы админка могла показать «висит незавершённый батч».

### 4.3 Двойной клик по «Перенести» кладёт файл нулевого размера  `[medium, race]`

**Где:** `src/components/admin/ClientCard.tsx:164`

Запрос A переносит файл; запрос B получает от `claimName` имя `Track_2.mp3`
(создав его **пустым**) и падает на rename с ENOENT. В папке клиента остаётся
нулевой mp3 — он попадёт в библиотеку и в плеер.

**Правка.** Guard на in-flight в `doMove` + `disabled` на кнопке. На сервере — в
catch удалять созданный placeholder.

### 4.4 Чипы категорий кликабельны во время «применить»  `[medium, race]`

**Где:** `src/components/ClassifyBatch.tsx:61`

Кнопки серые, но чипы живые: UI показывает новую категорию, а PUT прилетает после
того, как confirm уже разложил файлы. Трек уезжает в старую категорию, экран
показывает новую.

**Правка.** Прокинуть `busy` в `TrackRow` и игнорировать `onToggleCat`, пока идёт
confirm.

### 4.5 Токен не привязан к паролю  `[medium, security]`

**Где:** `server/http.mjs:126-128`, `server/crypto.mjs`

Payload токена — `{ u, exp }`. Сброс пароля клиента меняет хеш, но **не отзывает
выданные токены**: планшет бывшего заведения продолжает работать 30 дней. Если
клиент удалён и создан новый с тем же username, старый токен «переезжает» на него.

**Правка.** Привязать токен к версии учётки: класть в payload часть соли и
сверять в `authUser`. Сброс пароля меняет соль → все старые токены мертвы.

### 4.6 Успешный вход обнуляет rate-limit всего IP  `[low, security]`

**Где:** `server/router.mjs:73`, `server/http.mjs:94-108`

`clearLoginAttempts(ip)` чистит бакет **всего IP**. Сотрудник со своей рабочей
учёткой может гонять цикл «10 попыток подбора чужого пароля + один свой успешный
вход» и обходить лимит бесконечно.

**Правка.** Ключевать лимитер парой IP+логин и чистить только свой бакет.

### 4.7 `saveUsers()` глотает ошибку записи  `[low]`

**Где:** `server/users.mjs:46-55`

`.catch(e => console.error(...))` возвращает **успешный** промис, поэтому роут
создания клиента отвечает 201 и показывает одноразовый пароль, которого нет на
диске. При переполнении диска (а `DATA_DIR` по умолчанию на одном томе с
`MUSIC_ROOT`, куда льются батчи до 2 ГБ) клиент выглядит созданным, но исчезнет
после рестарта.

**Правка.** Разделить цепочку и результат: очередь продолжает жить, но вызывающий
получает реальную ошибку и отвечает 500.

### 4.8 `memo(TrackList)` пробит инлайн-стрелкой  `[low, perf]`

**Где:** `src/components/PlayerScreen.tsx:695` — `onClose={() => setListOpen(false)}`

Новая функция на каждый рендер обнуляет `memo`: при открытой панели список из
200–400 кнопок реконсилируется ~4 раза в секунду.

## 6. Требуют проверки перед правкой

Верификатор среза «ресурсы сервера» вернул вердикты, не сопоставившиеся с
находками, поэтому эти шесть **не прошли состязательную проверку** — их нельзя
считать ни подтверждёнными, ни опровергнутыми. Перед правкой проверить каждую по
коду отдельно.

1. **Публикация недописанного файла в живой папке клиента** — `server/uploads.mjs:103`.
   `claimName` создаёт файл заранее (`open 'wx'`), и он виден `scanFolder` до
   конца записи. В паре с §3.3 (кэш не инвалидируется) даёт обрезанный трек в
   кэше планшета навсегда. **Приоритетная к проверке.**
2. **`scryptSync` блокирует event loop** — `server/crypto.mjs:43`. Синхронный
   scrypt на публичном `/auth/login`, в том числе на неудачных попытках и на
   decoy-хеше. На время его работы встаёт раздача аудио.
3. **Дочерние python-процессы переживают рестарт node** — `server.mjs`/`classify.mjs`.
   Сейчас неактуально: VEclassify на проде не развёрнут.
4. **Нет TTL у staging-папок классификации** — `server/classify.mjs:195`.
5. **stdout/stderr классификатора копятся в heap весь час прогона** — `classify.mjs:247`.
6. **Нет ограничения на число одновременных классификаторов** — `classify.mjs:234`.

Пункты 3–6 касаются только моста VEclassify.

## 7. Опровергнуто — не возвращаться

Проверены скептиком и отклонены с обоснованием:

- **Закрытое соединение IndexedDB убивает воспроизведение** — цепочка действительно
  не обёрнута в catch, но триггер недостижим в описанном виде.
- **Клик по чипу пересортировывает таблицу под курсором** — механика подтверждена,
  но группировка по категориям здесь осознанная, дефектом не является.
- **Переключатель флагов клиента отдаёт старое значение** — фактура верна, но
  повторный PUT идемпотентен, сценария отказа нет.
- **`readBody` портит многобайтный символ на границе чанка** — код описан верно,
  но на этом сервере нет маршрута, чьё тело могло бы разорваться между `data`.

## Воспроизведение измерений

Профайлер живёт **вне репозитория** (в `devDependencies` он заставил бы прод
тянуть puppeteer при каждом `npm ci`). Нужен установленный Chrome; скрипт
логинится, прогревается, снимает снимок кучи после принудительного GC, гоняет
соак и сравнивает:

```bash
npm i puppeteer-core          # в отдельном каталоге, не в проекте
node leak.mjs --skips 200     # ключи: --url --user --pass --chrome
```

Скрипт разбирает `.heapsnapshot`, считает узлы по типам и ловит detached DOM.
По канону портфеля постоянное место для такого инструмента — `platform/tooling/`,
а не продуктовый репозиторий.

Счётчик роста графа (то, чем измерена §2.2) — в консоли страницы:

```js
const AC = window.AudioContext || window.webkitAudioContext
let n = 0; const o = AC.prototype.createMediaElementSource
AC.prototype.createMediaElementSource = function (...a) { n++; return o.apply(this, a) }
// далее переходы плеер↔админка; n не должен расти после правки §2.2
```
